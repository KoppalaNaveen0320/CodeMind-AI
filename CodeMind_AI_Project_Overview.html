1. Executive Summary & Mission

CodeMind AI is an enterprise-grade, repository-independent code intelligence platform designed to eliminate the engineering overhead of onboarding, auditing, and maintaining complex multi-language codebases. While traditional code assistants rely on naive text similarity search or external cloud services that breach repository confidentiality, CodeMind AI couples Tree-Sitter Abstract Syntax Tree (AST) parsing, lexical BM25 ranking, and dense semantic vector search (pgvector HNSW) with an on-premises local LLM execution runtime.

The primary design imperative of CodeMind AI is verifiable, source-grounded code intelligence: when an engineer queries an unfamiliar repository, CodeMind must provide precise, multi-file execution traces with exact file paths and line ranges, and explicitly refuse to hallucinate absent features or speculative functions.

  • Strict Cross-Repository Isolation: Zero data leakage between indexed repositories in multi-tenant environments.

3. Core Intelligence Pipelines

3.1 Semantic Indexing Pipeline (IndexingService)

When a repository is imported via local path or cloned from GitHub, CodeMind AI executes a deterministic, multi-stage ingestion pipeline designed for high throughput and memory safety:

  1. Traversal & Exclusion: Recursively scans source directories while respecting .gitignore, excluding binary artifacts (.dll, .so, .exe), lock files (pnpm-lock.yaml, package-lock.json), and virtual environment directories.
  2. SHA-256 Content Hashing: Generates cryptographic hashes for each file to ensure idempotency and enable selective incremental indexing.
  3. Symbol-Aware Code Chunking: Rather than arbitrary token slicing, CodeMind partitions code along function, class, and interface boundaries using language-specific AST segmenters. Each chunk records chunk_index, start_line, end_line, code_symbol, and language metadata.
  4. Batch Vector Embedding: Batches chunks in groups of 32 for dense vectorization using Ollama's nomic-embed-text (768-dimensional float arrays). Failed batches trigger atomic database rollbacks.
  5. Graph Materialization: Simultaneously extracts imports and function calls, inserting nodes into graph_nodes and relationships into graph_edges.

3.2 Hybrid Retrieval Engine (HybridEngine)

Code search queries are dispatched to a dual-channel retrieval engine that addresses the limitations of pure vector search (which struggles with exact symbol names) and pure keyword search (which fails on conceptual queries):

Hybrid Retrieval Formulation

Given query q and repository filter R_id, the hybrid score S(c, q) for chunk c in R_id combines cosine similarity and BM25 relevance:

S(c, q) = 0.60 × (1 - CosineDistance(v_q, v_c)) + 0.40 × BM25(c_text, q_tokens)

Where v_q is the 768-dimensional query embedding, and the vector distance is evaluated via PostgreSQL pgvector HNSW index: embedding <=> CAST(:query_vector AS vector).

3.3 Grounded Assistant & Hallucination Elimination (AssistantService)

The assistant pipeline employs a two-tier verification architecture that enforces strict factual grounding:

  • Prompt-Time Context Injection: Only top-k retrieved chunks matching repository ID constraints are injected into the system prompt with strict bounding tags ([CHUNK <id> FILE <path>:<start>-<end>]).
  • Pre-Execution Refusal Classification: Queries addressing non-existent files or absent functionality are evaluated against symbol indexes. If no relevant symbols exist, the engine issues an explicit refusal ("UNVERIFIED / ABSENT"), preventing speculative generation.
  • Post-Synthesis Citation Auditing: The generated text is scanned for file and line references. Any citation that does not match an indexed chunk in the database is stripped prior to transmission to the user.

4.3 Key Performance Benchmark Insights (AUTH-01)

  • Client Semaphore Bottleneck Discovery: The live HTTP benchmark reported ~5.5s for 500 requests with 50 concurrency. Source inspection and execution proved the server was not queueing; client-side tasks were blocked waiting for an admission semaphore. Once dispatched, server round-trip latency was under 220 ms.
  • Sync vs Async CPU Offloading: Synchronous endpoints offloaded to worker threads via AnyIO (111.16 req/s) outperformed asynchronous CPU endpoints (107.67 req/s), proving that async is not universally faster when computation blocks the event loop.

Based on empirical evidence gathered during the evaluation, the following prioritized roadmap guides CodeMind AI's next evolutionary phases:
